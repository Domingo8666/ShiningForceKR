# v5.1 한국어 엔진 정적 구조

상태: verified-static

검증일: 2026-07-29

## 검증 방법

원본 ROM은 사용하지 않았습니다. v5.1 BPS의 TargetRead 데이터와 known-mask만 복원했고, 패치 CRC와 액션 스트림을 먼저 검증했습니다. 확장 구간 0x80000..0x17C000은 1,032,192바이트 전부가 BPS 자체에서 복원됩니다.

## 재배치된 한국어 Huffman 블록

| 항목 | 값 |
|---|---:|
| ROM 뱅크 | 0x20 |
| 벡터 파일 오프셋 | 0x80100 |
| 벡터 논리 주소 | 0x4100 |
| 벡터 엔트리 | 256 |
| 존재하는 트리 | 51 |
| 빈 트리 | 205 |
| 심벌/트리 데이터 | 0x80300..0x808D3 |
| 트리별 잎 수 | 1..38 |

존재하는 문맥 심벌은 다음과 같습니다.

~~~text
0x00..0x20  0x5F 0x64 0xC9 0xCA 0xCC 0xCD 0xCF 0xD0 0xD1
0xD2 0xD4 0xD5 0xD6 0xD8 0xD9 0xDB 0xDC 0xDD
~~~

각 포인터가 가리키는 MSB-first 트리와 역순 잎 심벌을 전부 파싱했습니다. 모든 트리의 심벌 시작과 구조 끝을 합치면 0x80300..0x808D3이 빈틈 없이 정확히 재현됩니다. 따라서 영어판 0x29C3F 벡터를 한국어 v5.1에 대입하면 안 됩니다.

## 한국어 글꼴 런타임

- 주 루틴: 0x87000..0x8730B
- 보조 루틴: 0x87A00..0x87A9D
- 페이지 매핑: 0x87400..0x874F4, 244엔트리
- 페이지 매핑 SHA-256: 48304fe0df1f162f4fad4c50d6fb7761bc9ddb315a4300f00af07df3a0a644f7
- 글꼴 데이터 뱅크: 0x22..0x5E
- 0x22..0x5D의 60개 뱅크는 뱅크 앞 0x3000을 사용하는 동일한 배치를 가집니다.
- 마지막 0x5E 뱅크의 마지막 비-0xFF 바이트 다음 위치는 0x1798DF입니다.

244엔트리 매핑과 61개 글꼴 데이터 뱅크의 관계는 런타임의 페이지 선택 규칙을 추적할 때 쓰는 확정 기준입니다. 같은 바이트 값이라도 영어 엔진의 토큰 의미를 한국어 엔진에 그대로 적용하지 않습니다.

## 전체 ROM 소비 후보 스캐너

tools/v5_1_consumer.py는 S25U에서 빌드된 전체 v5.1 ROM의 크기와 CRC32를 먼저 확인한 뒤 다음을 자동 기록합니다.

- 논리 주소 0x4100, 0x7000, 0x7A00 및 매퍼 레지스터 0xFFFE/0xFFFF의 Z80 모양 리터럴 좌표
- bank+addr 및 addr+bank 순서의 연속 3바이트 포인터 후보
- 같은 슬롯 안에서 단조 증가하는 보수적 2바이트 주소표 후보
- 3바이트 후보가 한국어 문맥 트리로 제한 안에서 종료되는 비율

출력에는 ROM 원문, 압축 바이트나 디코딩 문자열을 넣지 않습니다. 리터럴과 포인터 모양은 실행 중 소비 증거가 아니므로 candidate 상태로만 기록합니다.

tools/v5_1_trace_plan.py는 상위 후보마다 표가 들어 있을 수 있는 물리 ROM 뱅크와 slot 0/1/2의 가능한 Z80 논리 주소를 분리합니다. 주소를 포함한 명령 모양의 개수로 우선순위만 조정하고, emucap Game Gear 어댑터용 smsMemory read breakpoint 범위와 0xFFFC..0xFFFF 매퍼 스냅샷 계획을 생성합니다. 브레이크포인트가 실제로 발화하기 전에는 소비자 확정으로 표시하지 않습니다.

2026-07-29 S25U 첫 후보 탐색 관측은 3바이트 후보 110개, 2바이트 후보 50개, 당시 스캐너 최상위 물리 좌표 0x000B7D였습니다. 첫 교차 참조 점수식은 물리 0x010000의 190개 2바이트 후보를 선택하고 논리 0x4000/0x8000 모양 참조 46개를 집계했습니다. 그러나 이 주소들은 뱅크 슬롯 시작점이라 JP/CALL 등 무관한 제어 흐름이 많이 겹칩니다. 이 결과는 소비 증거로 승격하지 않았고, 점수식 v2는 제어 흐름 모양을 보고만 하되 승격 점수에서 제외하고 뱅크 리터럴과 결합되지 않은 슬롯 시작 주소를 감점합니다.

점수식 v3는 단순히 근처에 `LD A,bank` 모양이 있는 경우와, 그 값이 후보 논리 주소의 슬롯에 대응하는 Sega mapper 레지스터(0xFFFD/0xFFFE/0xFFFF)에 실제로 쓰이는 모양을 분리합니다. 같은 32바이트 관측 창 안에서 `LD A,bank` 뒤 16바이트 이내에 일치하는 `LD (mapper),A`가 있을 때만 강한 우선순위를 줍니다. 다른 슬롯 레지스터 쓰기와 뱅크 리터럴 단독 출현은 보고에는 남지만 소비 증거로 승격하지 않습니다.

S25U v3 관측에서 최상위 후보는 0x000B7B의 `addr_le_bank` 60개 항목이었고, 2위는 0x000B7A의 `bank_addr_le` 60개 항목이었습니다. 두 후보는 같은 180바이트 영역을 1바이트 차이로 해석하며 어느 쪽도 정적 포인터 적재 모양이 없습니다. trace-plan v4는 하나를 확정하지 않고 90% 이상 겹치는 같은 폭의 시프트 후보를 정렬 클러스터로 묶어 0x000B7A..0x000C2E 합집합을 실행 감시합니다. 구조·종료율 집계는 후보 비교용으로 공유하되 여전히 실행 소비 증거로 승격하지 않습니다.

## 아직 완료가 아닌 항목

- 상위 조회표 후보를 읽는 실제 소비 코드와 실행 중 뱅크 상태
- 0x00..0x20 및 제어 심벌의 화면 의미 전체
- 엔트리별 왕복 인코딩
- 목표 인트로 문장과 기존 한국어 문장의 정확한 엔트리 ID
- 콜드 부팅 에뮬레이터 검증

조회표를 거치지 않고 압축 영역의 임의 바이트에서 디코딩한 결과는 증거로 사용하지 않습니다. 위 항목이 끝나기 전에는 어떤 자유 번역문도 빌드 가능 상태로 표시하지 않습니다.

상위 3바이트 조회표 후보 4개에는 모든 엔트리를 대상으로 한 ROM 비포함
집계도 생성합니다. 집계 필드는 시도 수, 제한 안에서 종료된 수, 심벌 길이의
최솟값·중앙값·최댓값, 고유 대상 수·비율과 전체 대상 범위뿐입니다. 이 결과는
한 바이트 시프트 정렬을 고르는 보조 근거이며, 실행 중 read breakpoint와
매퍼 상태가 맞기 전에는 소비자 확정 근거가 아닙니다.
